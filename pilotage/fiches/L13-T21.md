## Contexte
Spec 13, fichier 04, R12 : associé unique (SASU, EURL) : décision de l'associé unique seule ; SARL pluripersonnelle : convocation, ordre du jour, feuille de présence, PV d'AG ; SAS pluripersonnelle : selon les statuts (`assemblee.mode_decision`). Chaque document porte la version et la date du modèle et la mention « Préparé par IA, à faire valider ». Modèle sans version approuvée : refus, « modèle à faire valider ». Tests MOT84-1 à MOT84-3 (la feuille de présence est « à vérifier » : contenu selon les statuts).

## À faire
1. `packages/noyau/src/assemblee/documents.ts` :
   - `documentsAssemblee(societe { forme; nbAssocies; modeDecision? }, modeles { type; version?; dateModele?; approuve }[])` ;
   - associé unique (nbAssocies = 1) : `decision_associe_unique` ; SARL à plusieurs : `convocation`, `ordre_du_jour`, `feuille_presence`, `pv_ag` ; SAS à plusieurs : mode `assemblee` comme la SARL, `consultation_ecrite` : `consultation_ecrite` et `pv_consultation`, `acte_unanime` : `acte_unanime` ; mode absent : refus `mode_decision_absent` ; EI : `non_applicable` ;
   - chaque document : `{ type; versionModele; dateModele; mention: prepare_par_ia_a_faire_valider; aVerifier }` (`aVerifier` vrai pour `feuille_presence`) ;
   - un modèle requis absent ou non approuvé, ou sans version ou date : refus `modele_a_faire_valider` avec la liste triée des types en cause, AUCUN document produit ;
   - nbAssocies non entier, NaN, Infinity ou inférieur à 1 : `ErreurAssemblee('entree_invalide')`.
2. Tests nommés : `associe-unique-une-decision` (MOT84-1), `sarl-quatre-documents` (MOT84-2), `sas-selon-le-mode`, `mode-absent-refuse`, `modele-non-approuve-zero-document` (MOT84-3), `version-date-et-mention-presentes`, `ei-non-applicable`, `nb-associes-invalide`.
