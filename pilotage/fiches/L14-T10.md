## Contexte
Spec 14, `03`, JUR-002. L'éligibilité à la dispense se calcule à la date de clôture depuis le profil (forme, total du bilan, chiffre d'affaires net, effectif) avec la règle datée `jur.rapport_gestion.dispense` (À VÉRIFIER : critères, seuils, règle des exercices consécutifs, exclusions). Éligible : statut `dispense`, rien n'est généré. Non éligible, ou une donnée manque : JAMAIS d'hypothèse ; rapport simple en `brouillon` et une question pour la donnée manquante. Les activités exclues (ex. gestion de titres de participations) ne sont jamais dispensées. La SCI relève de JUR-014 (L14-T13). Tests G1, G2, G3.

## À faire
1. `packages/noyau/src/juridique/rapport-gestion.ts` (classe locale `ErreurRapportGestion`) :
   - `RegleDispense { formesConcernees: readonly string[]; seuils: { bilanCentimes: number; chiffreAffairesCentimes: number; effectif: number }; maxSeuilsDepasses: number; depassement: 'strict' | 'large'; activitesExclues: readonly string[] }` (toutes les valeurs viennent du paramètre daté, passé en argument) ;
   - `ProfilCloture { forme: string; bilanCentimes: number | null; chiffreAffairesCentimes: number | null; effectif: number | null; activite: string | null }` ;
   - `decisionRapportGestion(profil, regle)` → `{ statut: 'dispense' } | { statut: 'brouillon'; motif: 'seuils_depasses' | 'activite_exclue' | 'donnee_manquante' | 'forme_non_concernee'; questions: readonly ('bilan' | 'chiffre_affaires' | 'effectif' | 'activite')[] }` ; ordre : forme non concernée, puis activité (absente = question), puis exclusion, puis données manquantes (une question par donnée), puis seuils.
2. Tests nommés (seuils INVENTÉS de la spec : 100 000 000 / 200 000 000 centimes / 20 ; règle de test : au plus 1 seuil dépassé ; SIREN fictifs) : `g1-sous-les-seuils-dispense`, `g1-effectif-absent-brouillon-et-question`, `g2-un-seul-seuil-depasse-dispense`, `g2-deux-seuils-depasses-brouillon`, `g3-activite-exclue-jamais-dispensee`, `g3-activite-absente-question`, `egalite-au-seuil-selon-le-mode` (strict et large donnent deux résultats différents), `forme-non-concernee-brouillon`.

## Hors périmètre
Pas de génération du texte du rapport, pas de validation (double facteur : L14-T39, bloquée), pas de SCI (L14-T13).

## Pièges
Règles du noyau comme L14-T02. Aucun seuil, aucune forme (« SARL », « SAS »…) et aucune activité en dur dans src : tout vient de `RegleDispense`. Cas limites exigés : seuils NaN, négatifs, non entiers ou Infinity (refus) ; effectif négatif ou non entier (refus) ; total du bilan négatif (refus `bilan_negatif`, fixé par un test) ; `maxSeuilsDepasses` hors 0 à 3 (refus) ; listes vides.
