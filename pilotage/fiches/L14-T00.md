## Contexte
Spec 14, `01` partie D (DEC-044) : catalogue `docs/formats.csv` (code, sens, phase, exigence, test_id, niveau_test, ecran, outil_chat). Règle 1 : un format MVP sans `test_id` existant, ou dont le test n'est ni un aller-retour ni un passage au validateur officiel, fait échouer la CI. Règle 2 : `ecran` ou `outil_chat` vide = avertissement. Règle 3 : un format ajouté dans le code sans ligne au catalogue fait échouer la CI. `scripts/verifier.mjs` lance déjà TOUT fichier `outils/gardes/*.mjs` et `node --test outils/gardes/test/*.test.mjs` : aucun `package.json` à toucher.
Aujourd'hui presque aucun test d'aller-retour n'existe : si la règle 1 s'appliquait à toutes les lignes, la CI serait rouge dès la fusion. Choix de cette fiche (réversible, écart à la spec signalé dans LOT-14-PLAN) : une colonne de plus, `controle` = `actif` ou `prevu`.

## À faire
1. `docs/formats.csv`, en-tête exact : `code,sens,phase,exigence,test_id,niveau_test,ecran,outil_chat,controle`. Lignes initiales, toutes `controle=prevu`, `test_id` vide : `fec_export` (export), `fec_import` (import), `releve_csv`, `releve_ofx`, `releve_camt`, `releve_xlsx`, `releve_pdf` (import), `facture_facturx`, `facture_ubl`, `facture_cii` (import), `piece_pdf`, `piece_image`, `piece_zip` (import), `ventes_csv` (import), `grand_livre`, `balance`, `journaux` (export), `export_expert` (export), `export_complet_signe` (export). `exigence` : celle de la spec du format (DEC-030 pour le FEC, sinon l'exigence citée par la spec ; DEC-044 si aucune). `phase` : celle de la spec du format ; si inconnue, `P7` (ne rien inventer).
2. `outils/gardes/formats.mjs` (même structure que `outils/gardes/controles.mjs` : fonctions pures exportées, puis bloc d'exécution) :
   - `lireCatalogue(texte)` → lignes ; erreur si en-tête différent, nombre de colonnes faux, code en double, `sens` hors {import, export}, `controle` hors {actif, prevu}, `niveau_test` hors {aller_retour, validateur_officiel, vide} ;
   - `analyserCatalogue(lignes, testsConnus: Set<string>, codesDansLeCode: Set<string>)` → `{ erreurs: string[]; avertissements: string[] }` : ligne `actif` sans `test_id`, avec un `test_id` inconnu, ou avec `niveau_test` vide = erreur ; ligne `prevu` dont le `test_id` existe déjà = erreur « passer à actif » ; `ecran` ou `outil_chat` vide = avertissement ; code de `codesDansLeCode` sans ligne = erreur (règle 3) ;
   - `testsDuDepot()` : noms de tests trouvés par `git grep` sur `it('…'` et `test('…'` dans les fichiers `*.test.*` ; `codesDuDepot()` : valeurs de `export const CODE_FORMAT = '…'` dans `packages/*/src` et `apps/*/src` (convention posée par cette fiche, écrite en commentaire de tête).
3. Tests nommés (`outils/gardes/test/formats.test.mjs`, textes en mémoire sauf le dernier) : `entete-different-rouge`, `code-en-double-rouge`, `actif-sans-test-rouge`, `actif-test-inconnu-rouge`, `prevu-dont-le-test-existe-rouge`, `ecran-vide-avertissement-seul`, `format-du-code-sans-ligne-rouge`, `catalogue-du-depot-vert`.

## Hors périmètre
Aucun test de format (chaque lot de format écrit le sien et passe sa ligne à `actif`). Pas de `docs/fec_regles.csv` (lot 03, L03-T06). Ne pas modifier `scripts/verifier.mjs` ni un `package.json`.

## Pièges
Fiche sensible (`outils/gardes/`). Cas limites exigés en test : fichier vide, ligne vide finale (acceptée), fins de ligne CRLF (acceptées), BOM en tête (refusé, message clair), champ entre guillemets (refusé : le catalogue n'en a pas besoin), espace autour d'une valeur (refusée). Le test `catalogue-du-depot-vert` lit le vrai fichier : il rougit si une ligne est mal formée. Les avertissements vont sur la sortie d'erreur avec un code de sortie 0.
