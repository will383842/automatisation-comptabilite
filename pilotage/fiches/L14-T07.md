## Contexte
Spec 14, `01` partie E (DEC-004 : V1, mais phase serveur P5). `connecteur_sante` (connecteur, dernier_ok, echecs_consecutifs, etat : ok, degrade, panne). Un script sans IA vérifie chaque connecteur une fois par jour ; 2 échecs de suite = `degrade`, affiché au client avec la conduite à tenir ; retour à `ok` = bandeau retiré. Test D1. Le nombre d'échecs est un ARGUMENT.

## À faire
1. `packages/noyau/src/sources/connecteurs.ts` (classe locale `ErreurConnecteur`) :
   - `SanteConnecteur { connecteur: string; dernierOk: string | null; dernierEssai: string | null; echecsConsecutifs: number; etat: 'ok' | 'degrade' | 'panne' }` ;
   - `santeInitiale(connecteur)` ;
   - `enregistrerEssai(sante, { jour: string; ok: boolean }, { echecsAvantDegrade: number; echecsAvantPanne: number | null })` → nouvelle santé : succès = `ok`, compteur à 0 ; échec = compteur + 1, `degrade` au seuil, `panne` au second seuil s'il existe ;
   - `bandeau(sante)` → `'connecteur_degrade' | 'connecteur_en_panne' | null`.
2. Tests nommés : `deux-echecs-degrade` (D1), `succes-le-troisieme-jour-bandeau-retire` (D1), `un-echec-reste-ok`, `seuil-de-panne-optionnel`, `meme-jour-deux-fois-refuse`, `jour-anterieur-refuse`.

## Hors périmètre
Pas de script planifié ni d'appel aux services (L14-T38, bloquée). Aucune donnée client.

## Pièges
Règles du noyau comme L14-T02. Cas limites exigés : seuils NaN, nuls, négatifs, non entiers ou Infinity (refus) ; `echecsAvantPanne` inférieur ou égal à `echecsAvantDegrade` (refus `seuils_incoherents`) ; jour mal formé ; nom de connecteur vide.
