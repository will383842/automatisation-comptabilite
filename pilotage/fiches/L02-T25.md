## Contexte
Spec 02, fichier 04 : « Pseudonymisation avant tout appel IA : IBAN, noms de personnes physiques, numéros de carte → jetons stables (`[PERSONNE_7]`) ; la table de correspondance ne quitte pas la base de la société. » Test T04-5 : relevé de 140 lignes avec 12 IBAN et 4 noms de personnes → 0 IBAN, 0 nom en clair dans ce qui part vers l'IA. Principe 4 du bloc : le texte des relevés est une donnée, jamais une consigne. L'appel à l'IA lui-même est bloqué (D43) ; cette fonction doit exister AVANT.

## À faire
1. `packages/noyau/src/banque/libelles/pseudonymiser.ts` :
   - `pseudonymiser(textes: readonly string[], personnes: readonly string[], tableExistante?: Map<string, string>)` → `{ textes: string[]; table: Map<string, string> }` ;
   - IBAN (forme pays + 2 chiffres + 11 à 30 caractères, avec ou sans espaces) → `[IBAN_n]` ; suites de 12 à 19 chiffres ou `X` → `[CARTE_n]` ; chaque nom de `personnes` (comparaison sans casse ni accents, dans les deux ordres prénom/nom) → `[PERSONNE_n]` ;
   - jetons STABLES : un même original reçoit le même jeton dans tous les textes et d'un appel à l'autre si `tableExistante` est fournie ; `n` croissant dans l'ordre de première rencontre ;
   - `retablir(texte, table)` : remplace les jetons par les originaux (pour l'affichage dans la société seulement) ;
   - consignes dans un libellé : laissées telles quelles (c'est la passerelle qui les traite comme données) ; aucune interprétation.
2. Tests nommés : `iban-remplace-avec-et-sans-espaces` (IBAN à clé FAUSSE), `carte-remplacee`, `personne-dans-les-deux-ordres`, `jeton-stable-entre-textes`, `jeton-stable-entre-appels`, `retablir-inverse-exact`, `t04-5-zero-en-clair` (140 libellés générés à graine fixe, 12 IBAN, 4 noms : aucune occurrence en sortie), `nom-partiel-non-remplace` (« DUPONTEL » ne devient pas `[PERSONNE_1]`).

## Hors périmètre
Appel au modèle (bloqué : L02-T65). Stockage de la table (bloqué : L02-T62). Liste des personnes (annuaire des associés : autre fiche).

## Pièges
Cas limites exigés : textes vides, personne vide (ignorée), deux personnes dont l'une contient l'autre (la plus longue d'abord), jeton déjà présent dans le texte d'origine (`[PERSONNE_1]` écrit par un tiers : échappé pour que `retablir` ne le remplace pas). Aucun IBAN à clé juste dans les tests (`garde:fictif`). Sensible (sécurité). Règles du noyau.
