## Contexte
Spec 15, EX-R4 (sécurité) : pour TOUTE cellule texte (libellés, noms, références, commentaires, en-têtes, étiquettes de total, filtres rappelés), si le PREMIER caractère est `=`, `+`, `-`, `@`, tabulation (U+0009), retour chariot (U+000D), saut de ligne (U+000A) ou une variante pleine chasse (`＝` U+FF1D, `＋` U+FF0B, `－` U+FF0D, `＠` U+FF20), la valeur est préfixée d'une apostrophe. Point S1 (recommandation retenue) : l'apostrophe reste visible, y compris en XLSX. Les cellules nombre ou date produites par le serveur ne sont pas préfixées ; une valeur d'une colonne entier ou centimes qui ne respecte pas `^-?\d+$` est traitée comme du texte. La base n'est jamais modifiée.

## À faire
1. `exports/neutraliser.ts` :
   - `CARACTERES_DANGEREUX` (liste gelée des 11 caractères, écrits par leur point de code `\u…`) ;
   - `neutraliserTexte(v: string): string` ; `''` reste `''` ; une valeur qui commence par un espace puis `=` reste telle quelle (cas limite de la spec) ;
   - `cellule(valeur: unknown, type: TypeColonne)` → `{ genre: 'texte'; valeur: string } | { genre: 'nombre'; valeur: string } | { genre: 'date'; valeur: string }` : `entier` ou `centimes` = nombre seulement si `typeof valeur === 'number'`, entier sûr (`Number.isSafeInteger`), sinon texte neutralisé (`NaN`, `Infinity`, `1.5`, `'12'`, `'=1'`) ; `date` = date seulement si chaîne AAAA-MM-JJ valide, sinon texte neutralisé ; `booleen` = nombre `1` ou `0` ; `null`/`undefined` = texte vide ; objet = erreur `type_invalide`.
2. Tests nommés : `chaque-caractere-dangereux-prefixe` (les 11), `caractere-au-milieu-intact`, `espace-puis-egal-intact`, `vide-intact`, `nombre-negatif-reste-nombre`, `entier-hors-forme-devient-texte` (`NaN`, `Infinity`, `1.5`, `'12'`, `'=1'`, `2 ** 60`), `date-invalide-devient-texte`, `apostrophe-initiale-non-doublee` (`'=1` reste `'=1` : il ne commence pas par un caractère dangereux), `entree-non-modifiee`.
