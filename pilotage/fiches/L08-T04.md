## Contexte
Spec 08, fichier 04 §2 : « Schéma compatible N et N-1 : toute migration est additive (expansion). Une colonne ou une table n'est retirée (contraction) qu'à la version N+2, quand plus aucune image N-1 ne tourne. » La console filtre déjà les ordres destructeurs à l'application (`migrer-base.ts`) ; cette garde arrête le problème plus tôt, dans la PR. Les migrations du module vivent dans `apps/serveur/src/base/migrations/*.sql` (fiches de persistance des autres lots, ex. L15-T59) ; aucune n'existe encore : la garde doit être verte sans fichier.

## À faire
1. `outils/gardes/migrations.mjs` (forme des autres gardes ; liste des fichiers par `git ls-files apps/serveur/src/base/migrations`, injectable pour les tests) :
   - `analyserMigration(texte, nom)` → problèmes `{ fichier, ligne, code }` ; commentaires `--` et `/* */` ignorés, chaînes `'…'` ignorées, casse ignorée ;
   - ordres refusés : `DROP TABLE`, `DROP COLUMN`, `DROP SCHEMA`, `DROP INDEX` hors `CONCURRENTLY IF EXISTS` d'un index créé dans le même fichier, `RENAME`, `ALTER COLUMN … TYPE`, `ALTER COLUMN … SET NOT NULL`, `ADD COLUMN … NOT NULL` sans `DEFAULT`, `TRUNCATE`, `DELETE`, `UPDATE` sans `WHERE` (code `ordre_destructeur` avec le mot fautif) ;
   - `analyserNoms(noms)` : noms `NNN-mot.sql` (3 chiffres, croissants sans doublon) ; doublon = `numero_en_double`, autre forme = `nom_invalide` ;
   - une migration déjà fusionnée ne doit pas changer : `analyserModifications(fichiersModifies)` (liste fournie par `git diff --name-status origin/main...HEAD`, injectable) rend `migration_modifiee` pour un statut `M` ou `D` sur un fichier de ce dossier.
2. Tests nommés : `dossier-absent-vert`, `ajout-de-table-et-colonne-vert`, `drop-column-rouge`, `rename-rouge`, `not-null-sans-default-rouge` (et `NOT NULL DEFAULT 0` vert), `commentaire-et-chaine-ignores` (`-- DROP TABLE x` et `'DROP TABLE'` verts), `numero-en-double-rouge`, `migration-modifiee-rouge`.

## Hors périmètre
Contraction à N+2 (procédure à écrire quand une première contraction sera nécessaire : nouvelle fiche). Recette CI N-1 contre N sur une vraie base (fiche bloquée L08-T47). Aucune migration écrite ici.

## Pièges
Chemin `outils/gardes/` : sensible. Ne pas toucher `package.json` ni `scripts/verifier.mjs` (découverte automatique). Le découpage SQL est simple : un `$$ … $$` (corps de fonction) doit être ignoré comme une chaîne ; le tester. Cas limites : fichier vide (vert), fin de ligne CRLF, ordre écrit sur deux lignes (`DROP\n TABLE`).
