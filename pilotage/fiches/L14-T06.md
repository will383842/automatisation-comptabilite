## Contexte
Spec 14, `01` partie C. `sirene_cache` : siren, siret, reponse, etat_etablissement (actif, ferme), lu_le, expire_le. Règle 3 : le cache répond d'abord (durée en paramètre). Règle 4 : établissement fermé = carte « établissement fermé : vérifiez », la pièce reste lue. Règle 5 : identifiants d'accès suivis ; alerte 30 jours avant l'échéance ; service en panne = saisie à la main, rien de bloqué. Test S1 (fin) : second import des mêmes SIREN = 0 requête. Test S2 : jeton expirant dans 29 jours = alerte. Un cache par client (point 7 des points à trancher, recommandation suivie).

## À faire
1. `packages/noyau/src/sources/sirene-cache.ts` (classe locale `ErreurCache`) :
   - `interface Calendrier { ajouterJours(date: string, n: number): string }` injecté ;
   - `EntreeCache { numero; reponse: unknown; etat: 'actif' | 'ferme'; luLe: string; expireLe: string }` ;
   - `lireCache(cache, numero, maintenant)` → `{ etat: 'frais'; entree } | { etat: 'expire' } | { etat: 'absent' }` (expiré si `maintenant >= expireLe`) ;
   - `aDemander(numeros, cache, maintenant)` → numéros absents ou expirés, sans doublon, dans l'ordre reçu ;
   - `mettreEnCache(cache, entree)` → nouveau cache (remplace l'entrée du même numéro ; l'entrée reçue n'est pas modifiée) ;
   - `carteEtablissement(entree)` → `'etablissement_ferme' | null` ;
   - `alerteIdentifiants({ echeance; maintenant; joursAvant }, cal)` → booléen (vrai si `maintenant >= cal.ajouterJours(echeance, -joursAvant)`) ;
   - `repliPanne()` → `{ saisieManuelle: true; bloque: false }`.
2. Tests nommés : `second-import-zero-requete`, `entree-expiree-redemandee`, `expiration-a-l-instant-exact`, `etablissement-ferme-carte`, `identifiants-a-29-jours-alerte` (joursAvant 30), `identifiants-a-31-jours-pas-d-alerte`, `panne-saisie-manuelle-rien-de-bloque`.
