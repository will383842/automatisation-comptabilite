## Contexte
Spec 09, §05 : sociétés fictives Lemoine Rénovation (SARL, exercice du 01/07/2026 au 30/06/2027, tout confirmé sauf le régime de TVA), Atelier Bertin (EI au régime micro, services ; société en formation dans le jeu existant, SIREN nul), Boulangerie Rivoire (SAS). SIREN fictifs dont la clé de Luhn est juste : 123456782 et 987654324. Le jeu existant (`generateur.ts`, L00-T08 et L01-T22) a déjà Lemoine Rénovation et Atelier Bertin : garder les mêmes noms et SIREN.

## À faire
1. `packages/donnees-fictives/src/profil.ts` :
   - `genererProfils(graine = 1)` → `{ societes: { id; denomination; forme; siren: string | null; enFormation: boolean }[]; champs: ChampFictif[]; regimesTva: LigneRegimeFictive[]; regimesImposition: LigneImpositionFictive[]; parametres: ParametreFictif[]; identites: { siren; denomination; forme; viesNumero; vies: 'valide' | 'invalide' | 'indisponible' }[] }` ;
   - Lemoine Rénovation : tous les champs obligatoires `confirme` sauf `regime_tva` `a_confirmer` (cas P04) ; deux valeurs de forme datées pour un cas « forme changée » sur Boulangerie Rivoire (SARL puis SAS, cas P24) ; Atelier Bertin : `tenue = livre_recettes`, `en_formation = vrai` ;
   - origines variées (`document`, `sirene`, `saisie_personne`, `proposition_ia`), `source_ref` fictive (`piece-fictive-001#page=1`) ;
   - `parametres` : clés et valeurs INVENTÉES (`fictif.seuil_a`, `fictif.taux_b`), statuts `non_verifie`, `a_verifier`, `valide`, `retire`, sources sur un domaine officiel avec un chemin fictif ;
   - `perimetreFictif` : `{ formesHorsPerimetre: ['FORME_X'], prefixesPostauxExclus: ['99'] }` (listes INVENTÉES pour le serveur en mémoire ; les vraies sont dans L09-T28) ;

2.
