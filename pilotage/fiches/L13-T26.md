## Contexte
Spec 13, fichier 05, R04 : sans taux BCE pour la devise à la date de la pièce, l'écriture reste BROUILLON `taux_manquant` et une saisie est exigée : taux, source en texte (obligatoire), personne qui saisit ; sans source : `422 source_obligatoire`. R05 : un taux saisi est « à vérifier » jusqu'à confirmation ; il sert à un brouillon, jamais à une écriture VALIDÉE. R06 : parité fixe : taux saisi une fois avec source et date d'effet ; aucune recherche BCE après cette date. Cas limites : week-end = taux de la veille ouvrée ; taux saisi à 0 ou négatif refusé ; parité modifiée : l'ancienne ligne est close. Tests MOT96-1 à MOT96-5 (devises fictives XXD, XXC).

## À faire
1. `packages/noyau/src/change/taux.ts` (`estDateValide`, `comparerDates`, `ajouterJours` de `../dates/civiles.js`) :
   - `resoudreTaux({ devise; date }, sources { bce: { devise; date; tauxE8 }[]; saisis: { devise; date; tauxE8; sourceTexte; saisiPar; statut (a_verifier, ok) }[]; parites: { devise; tauxE8; effetDebut; effetFin (exclue) ou null; source; statut }[] }, joursMax)` ; ordre : parité en vigueur, puis BCE à la date ou au plus `joursMax` jours avant (la plus récente), puis taux saisi à la date ; sinon `{ ok: false; code: taux_manquant }` ; succès : `{ ok: true; tauxE8; origine (parite_fixe, bce, saisi); dateDuTaux; aVerifier }` ;
   - `saisirTaux({ devise; date; tauxE8; sourceTexte; saisiPar })` : taux nul, négatif ou non entier : `taux_invalide` ; source vide ou blancs : `source_obligatoire` (statut HTTP 422 dans l'erreur) ; personne vide : `saisie_anonyme` ; succès : statut `a_verifier` ;
   - `validationAutorisee(tauxResolu)` : faux si `aVerifier`.
