## Contexte
Spec 04, fichier 06 §1, cascade : (1) même SHA-256 = refus tôt ; (2) facture électronique : SIREN émetteur + numéro + date + TTC = doublon sûr ; (3) clé métier fournisseur + compte de facturation + numéro normalisé : même TTC = doublon sûr, TTC différent = collision signalée, jamais fusion ; (4) empreinte du texte normalisé = doublon proposé ; (5) image perceptuelle, distance <= seuil = proposé. « Numéros différents = jamais doublon, quel que soit le reste. » Tickets sans numéro : niveaux 4 et 5 plus fournisseur + date + TTC + heure ; sans heure : proposé. Pièce de référence : la meilleure qualité (XML > texte du PDF > photo), sinon la première arrivée. Cas T-LEC-2, 16, 17.

## À faire
1. `packages/noyau/src/pieces/classement/doublons.ts` :
   - `numeroNormalise(numero, prefixe?)` : majuscules, blancs, `-`, `/`, `.` retirés ; préfixe du compte de facturation retiré s'il est en tête ; zéros de tête de la partie numérique retirés ;
   - `texteNormalise(texte)` : minuscules, sans accents, sans blancs ni ponctuation (l'appelant en calcule l'empreinte) ;
   - `PieceComparee { id; sha256; electronique: boolean; sirenEmetteur?; fournisseurCle?; compteFacturation?; prefixe?; numero?; date?; heure?; ttc?: Centimes; texteNormalise?; distanceImage?: number; qualite: 'xml' | 'texte_pdf' | 'photo'; recueLe: string }` ;
   - `comparerPieces(nouvelle, existante, { distanceImageMax })` → `{ niveau: 1 | 2 | 3 | 4 | 5 | null; decision: 'fichier_identique' | 'doublon_sur' | 'collision_numeros' | 'doublon_propose' | 'aucun' }` : si les deux numéros normalisés existent et diffèrent = `aucun` AVANT tout autre niveau sauf le 1 ;
   - `pieceDeReference(a, b)` → id de la pièce gardée (qualité, puis `recueLe` le plus ancien, puis id).
